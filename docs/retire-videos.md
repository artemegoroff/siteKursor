# Переход с videos на courses

Меню, карточки главной и sitemap используют LearningCourse, LearningModule и
Lesson. Счётчики на главной считают уроки, включая подуроки, а не видеоблоки.
Курсы с уроками автоматически появляются в меню и на главной; пустой slug исключён. Лендинги выбираются из реестра LANDING_COURSES, учебные ссылки — из LearningCourse.

## Что удаляется

Удаляются рабочие модели Course, ProgrammTask и InputOutputData из videos,
их админка, обработчики, шаблоны и старые скрипты плеера/меню. Миграция
videos.0025 удаляет соответствующие таблицы и промежуточные таблицы связей.
Архивные практические задачи не преобразуются в LessonBlock и удаляются.
Материалы courses и данные ЕГЭ/ОГЭ остаются.

Каталог videos теперь содержит только служебную конфигурацию и историю миграций.
Он необходим: courses.0002 обращается к исторической модели videos.Course.
Простое удаление videos из INSTALLED_APPS нарушит граф миграций, в том числе
при создании базы с нуля. Исполняемых моделей videos больше нет.

## Старые ссылки

Перенаправления старых адресов настроены отдельно, поэтому механизм
перенаправлений через базу Django больше не используется. Рабочая модель,
регистрация в админке, обработчик и маршруты /old_course/ и /course/ удалены.
Django самостоятельно больше не обслуживает эти префиксы.

Миграция courses.0010 удаляет только таблицу соответствий старых адресов и её
данные. Курсы, модули, уроки и блоки сохраняются. Исторические миграции
courses.0008–0009 остаются: они входят в уже применённый граф и нужны для
последовательного развёртывания старых версий схемы. С нуля таблица временно
создаётся историческими миграциями, затем удаляется courses.0010.

Для выпуска удаления механизма достаточно выполнить `python manage.py migrate`
и перезапустить приложение. collectstatic для этой правки не требуется.

## Выпуск

1. Сохранить свежий дамп рабочей базы и проверить успешное завершение экспорта.
2. Проверить обновление на локальной копии MySQL, восстановленной из этого дампа.
3. На сервере остановить старые воркеры или включить режим обслуживания: старый
   код после удаления таблиц videos работать не сможет.
4. Установить код и зависимости, выполнить:

   ```sh
   python manage.py check
   python manage.py migrate --plan
   python manage.py migrate
   python manage.py collectstatic --noinput
   ```

   Исторический перенос courses.0009 выполняется до videos.0025; итоговая схема
   после courses.0010 уже не содержит таблицы соответствий старых адресов.
5. Перезапустить приложение способом, принятым на хостинге, и проверить главную,
   меню, sitemap.xml, уроки/подуроки и отдельно настроенные редиректы сервера.

Откат DeleteModel создаст пустые архивные таблицы, но не восстановит их строки.
Для восстановления старой версии с данными нужен сохранённый дамп и старый код.
Не удалять исторические миграции и не запускать migrate --fake.

## Проверки

```sh
python manage.py test courses
python manage.py makemigrations --check --dry-run
```

Тесты покрывают динамическое меню/главную, количество запросов, sitemap с
разреженными номерами заданий, обновление базы до и после первоначального
переноса архивных уроков и удаление таблицы старых адресов без потери материалов.


Обновлённая главная и поиск описаны в docs/home-page.md. Проверка выполнена на SQLite (новая база и обновление с историческими записями); перед выпуском повторите миграции на локальной копии рабочей MySQL из дампа. Старые таблицы действительно удаляются, данные courses и блоки не переносятся повторно. Это изменение заменяет прежнее предложение PR #9, а не требует его предварительного слияния.
